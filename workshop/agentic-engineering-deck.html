Why today

Same model. Different process.

Prompting and hoping (vibe coding)
type a wishget something backhope it's rightpaste the error in and repeat
Agentic engineering
agree on what "done" meanswrite it down where the agent can read itlet it loop until it's truecheck it yourself
Most bad results come from skipping the agreement step, not from a weak model.

Part 1 · The pieces

An LLM can only talk. An agent gives it a body.

The model is the LLM you already chat with: Gemini, Claude Opus 5.5, GPT-6 Astra. An agent gives it hands (tools to read files, run commands, open a browser) and a loop, so it keeps working until the job is done.

ChatGPT in a tab is the brain in the jar: it tells you what to do. Antigravity is the body: it does it in your files.
Part 1 · The harness

A harness turns a model into an agent

  • 1loop · plan, act, check, repeat
  • 2tools · files, terminal, browser
  • 3AGENTS.md · house rules it reads first
  • 4skills · recipes it loads when needed
  • 5subagents · helpers with one job each

Antigravity is a harness with an app around it. That's an ADE, an agentic development environment.

The next slides zoom into AGENTS.md, skills, subagents and the loop.
Piece 3 · AGENTS.md

House rules on the door

A markdown file the agent reads at the start of every conversation: how this project works, what to check before saying "done".

You don't need one today. When a project grows and you catch yourself repeating an instruction, that instruction belongs in AGENTS.md.

Say: "Every new conversation starts by reading this file. It's how I stop repeating myself." Antigravity also reads GEMINI.md.
Piece 4 · Skills

Recipes it pulls out only when needed

A skill is a folder with a SKILL.md inside: a process someone already worked out. Name one with / and the agent follows it, so you don't have to spell the steps out.

Type / in the chat to see all 29 you installed. The full list is in the skill reference at the end.

This is why today's prompts are short: the skill holds the process. Global skills live in ~/.gemini/config/skills; project skills in .agents/skills.
Piece 5 · Subagents

One manager, many small jobs

A subagent is a fresh agent sent off with one narrow job and a clean memory. It reports back a short summary, so the main agent stays focused.

Monolith agent: does every job in one conversation until it forgets the early details.

Orchestrator: hands out jobs, checks what comes back. Watch it live with /agents.

Antigravity's built-in subagents: research, browser and self. You don't ask for them; the loop sends them out.
Piece 1 · The loop

Plan, act, check, repeat. Then stop.

A loop is only as good as its finish line. It stops when:

  • ✳ every box on the checklist is ticked
  • ✳ it hits a round limit
  • ✳ the same problem keeps coming back
Without a finish line, a loop either stops too early or never stops. ralph-loop sets the limits itself; your job is the checklist.
The big idea

The agent forgets. Files don't.

Every new conversation starts from zero. Anything the agent must remember lives in a markdown file it reads. You don't write these; you check them.

PRODUCT.md

what we're building, and when it's done

end of grilling

GLOSSARY.md

the words you agreed on

written while grilling

AGENTS.md

how to work here

later, as you need it
This is why the grilling step ends with a file: the build reads PRODUCT.md, not the chat.

❓ Q1 · Who is it for? Just you, or your whole class?

❓ Q2 · How do you find a note? By module, by title, or by searching the text?

➡️ Recommended: yes for now, plus an "Export" button so you can back them up.

What you'll see

Answer every ❓

❓ is a decision the agent won't make for you. ➡️ is its guess.

Reply to all of them in one message: say yes, change it, or add what it missed.

It also saves the words you agree on (like "module" and "note") to GLOSSARY.md as it goes.

This is a mockup; your real one will ask different questions. The input line shows how to answer several at once.
# Lecture notes

## Problem
My notes are spread across five apps and I
can't find last week's lecture before a quiz.

## For
Me, on my laptop, during and after lectures.

## Out of scope
Login, sync, rich text, folders, sharing.

## Done when
- [ ] I can add a note with a module code and title
- [ ] Searching "lecture" finds "Lecture 3"
- [ ] Picking a module shows only its notes
- [ ] My notes are still there after a refresh

What and why, never how

Boxes you can check

Wrong? Say it in words

"No, it's just for me." It updates PRODUCT.md. This is the most important minute of the workshop.

Describe what's wrong, not how to fix it

before you change anything.
/agent-introspection-debugging You ticked
"search works" but it doesn't. Find out why your
check missed it, and fix both.
The second prompt is the interesting one: fix the process, not just the bug.
Before you share it

localhost is your room. A deploy is a billboard.

On localhost only you can see it. Deploy to Vercel and anyone with the link can, including people and bots you didn't invite.

Anything in the page can be read

So never put API keys or passwords in it.

Anyone can use it

Including bots, and they can run up your bill.

Ask before you ship

/security-audit If I put this on the internet, what could a stranger read, misuse, or break?

Third risk to say out loud: assume anything public has already been copied. We are not deploying today.
After today · resources

When you're ready to ship it for real

Put it online with Vercel

Free hosting with a public link. Ask the agent to deploy it with the Vercel CLI.

vercel.com/docs/getting-started-with-vercel

Add a database and logins with Supabase

The key in your page is public, so turn on Row Level Security for every table.

supabase.com/docs/guides/getting-started

Grill again first. Logins change what "done" means, so PRODUCT.md needs new boxes before the agent builds them.

Same method, bigger project: grill, check PRODUCT.md, build, then /security-audit.
